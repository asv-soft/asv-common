# Device addresses through client factories

The approved change adds protocol-neutral source addressing to existing client-device factories and restores `IDeviceExplorer.TryIdentify` as read-only lookup of discovered devices. MAVLink devices are identified by remote SystemId and ComponentId regardless of port.

- Add immutable `DeviceAddress` with canonical, non-empty `Family` and `Value` strings and ordinal value equality. Default is not a valid address.
- Add `TryGetSourceAddress(IProtocolMessage message, out DeviceAddress address)` and `TryGetDeviceAddress(DeviceId deviceId, out DeviceAddress address)` to `IClientDeviceFactory`, with default implementations returning false for existing external factories. Add virtual defaults to its generic base so protocol factories can override without restricting messages to the discovery type.
- Restore `IDeviceExplorer.TryIdentify(IProtocolMessage message, [NotNullWhen(true)] out DeviceId? deviceId)`. It extracts a source address through configured factories in existing Order and resolves only a currently discovered device. Unknown, unsupported and removed devices return false/null. It never calls discovery identification, creates devices or refreshes last-seen timestamps.
- User clarification: also expose both `TryGetSourceAddress(IProtocolMessage message, out DeviceAddress address)` and `TryGetDeviceAddress(DeviceId deviceId, out DeviceAddress address)` on IDeviceExplorer with compatible false defaults. DeviceExplorer delegates these pure extraction methods to its ordered factory snapshot, without requiring discovery, creating/updating devices or refreshing liveness. Null input throws; unsupported input returns false/default; invalid default addresses are not successful results.
- Keep factory discovery `TryIdentify`, creation and updates discovery-message-specific. Protocols without address support retain existing discovery behavior.
- Explorer owns address bindings. Bind when the device enters Devices, not only InitializedDevices. Deduplicate discovery by canonical address before creating another device, using the registered owning factory for updates. Keep bindings consistent during timeout and both disposal paths; no stale binding may survive removal or replace a newer registration.
- Keep public DeviceId equality unchanged. Use a consistent internal comparer honoring derived object equality/hash where existing DeviceId-keyed collections require full identity, rather than its class-only base IEquatable implementation.
- MAVLink implements both address hooks once in `MavlinkClientDeviceFactory<TDevice>`. Source accepts any MavlinkMessage; device identity uses MavlinkClientDeviceId.Id.Target. Canonical address is Family `mavlink`, Value invariant `systemId:componentId`. No port, endpoint, codec version, DeviceClass or local Id.Self participates. Factory discovery remains HeartbeatPacket-only.
- One logical address across ports means one live device. Different system/component pairs remain separate. Read-only lookup is source attribution, not TX destination resolution. Address extraction itself works before discovery; DeviceId lookup does not invent a device.
- Update focused tests and existing English documentation in both repositories. Do not modify generated packets, serialized identity formats or protocol wire behavior. Do not add address providers or a separate registry service.
- Preserve unrelated worktree changes. No commits, pushes, releases, remote changes or package publication. No dependency version bumps. Validate MAVLink against local common sources using an isolated temporary MSBuild import; published dependencies do not contain the new APIs yet.

Implementation approach: extending the existing factory boundary was selected over a new provider registry to avoid duplicate protocol registration and reuse shared MAVLink factory logic. Offline typed-device classification and changes to liveness policy are outside this change.
